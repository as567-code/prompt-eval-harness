# Decisions log

These are the binding rulings made while building Plan A1 (P0–P2). Each was made by the controller agent during subagent-driven execution, usually prompted by a reviewer finding or a live CLI observation, and recorded in this format: `decision — why — what it costs if wrong`. Where a ruling and the plan text conflict, the ruling wins. Where a ruling and the PRD conflict, the PRD was updated.

## Rulings

- **R1.** bandit runs as `bandit -c pyproject.toml -r src -ll` (medium severity and up) in pre-commit and CI, matching ROADMAP G1 — the plan's bare form fails on unavoidable low-severity subprocess notices — if wrong, low-severity issues go unreported, but they stay visible with a manual `bandit -r src`.
- **R2.** docker-marked tests auto-skip, via a `tests/conftest.py` hook, when `docker info` fails or `sandbox/IMAGE_ID` is missing. The coverage gate (`--cov-fail-under=85`) moves to the CI `sandbox` job, which runs the full non-live suite after `sandbox build`. The `checks` job runs `-m "not live and not docker"` without a coverage gate. Until T15 adds the sandbox job, the checks job keeps the gate. — Coverage must count the docker_runner code, which only the docker tests reach — if wrong, coverage is enforced one job later.
- **R3.** `FakeProvider.text(..., usage: Usage \| None = None)` defaults to `Usage(input=10, output=10)` inside the body — this satisfies ruff B008 — negligible if wrong.
- **R4.** the timeout test uses a unique sleep duration (`sleep 6061`) and checks for it with `pgrep -f "sleep 6061"` — this avoids false matches — negligible if wrong.
- **R5.** the T7 sanitizer drops every JSON key containing "credential", in addition to the path and id replacements — the test requires it, and the value is useless as a fixture — negligible if wrong.
- **R6.** `sandbox/IMAGE_ID` is gitignored and written by `promptharness sandbox build`. Docker tests read it, and skip if it is absent (R2). — Image IDs are per machine — if wrong, CI builds its own image first anyway.
- **R7.** the phase-gate steps (push, PR with the `ai-assisted` label, G2–G6, squash-merge, tag) are done by the controller after the phase's last task review is clean. Implementers stop at "Commit". — Skill rule: implementers never review or merge — if wrong, no cost.
- **R8.** the Task 7 sanitizer must also drop or placeholder every JSON key matching `(?i)(user_id\|account_id\|email\|credential)`. It must also replace the OS username everywhere, including in `-Users-<name>` tmp paths. `test_fixtures_present` asserts that the username and `/Users/` don't appear. — The repo is public, and Codex rollouts carry `creator_user_id`/`creator_account_id` — if wrong, the fixtures are slightly over-scrubbed.
- **R9.** Task 7 also captures one Claude call with `--output-format stream-json --verbose` (for the init event's auth-source field) and the output of `codex login status`, and records the field names in cli-notes.md. Task 12's `models verify`, and every live provider run, refuses to run unless Claude reports subscription (non-API-key) auth and Codex reports a ChatGPT login. — This closes the gap where an API key stored in CLI config bills real money — if wrong, live runs need one extra check call.
- **R10.** if Claude's OAuth fails under `safe_env`'s allowlisted env in Task 7, add only the specific variable it needs, ruled in the ledger. Never widen the allowlist generally. — Keeps the env minimal — if wrong, one more ledger entry.
- **R11.** the P1 brief for Task 6 must say that `run_cli`'s `extra_env` goes through `safe_env`, which now fails closed via `_EXTRA_ALLOWLIST`. Any new extra key needs an allowlist edit and a test. — Follows from the P0 fix I1 — negligible if wrong.
- **R12.** Claude tool audit. Without `json_schema`, require `num_turns == 1`. With `json_schema`, allow `num_turns <= 2`, but only if the result has the structured-output payload (per docs/cli-notes.md). Always require `permission_denials` to be empty. `--tools ""` disables every built-in tool, so the only tool left in a schema call is Claude Code's structured-output mechanism — if wrong, a schema call that misused another tool would be missed, but no such tool is available.
- **R13.** the Claude output cap (`CLAUDE_CODE_MAX_OUTPUT_TOKENS`) shows up as `is_error: true` with `api_error == "max_output_tokens"`, exit 1, and no partial text. The provider maps that to a Completion with `status=TRUNCATED`, `text=""`, `output_cap_applied=True`, and usage taken from the JSON. It is not a CliError. — In eval terms a capped attempt is "truncated", which is a graded outcome per PRD §5.8, not an infra error — if wrong, capped attempts would be miscounted.
- **R14.** the Codex output cap is unsupported (`model_max_output_tokens` is ignored). CodexCLIProvider never passes a cap and always sets `output_cap_applied=False`. Plan B's budget control (Bu) must handle OpenAI configs with attempt-level budgets only, and RESULTS must disclose that — this reflects real CLI behavior — if wrong, budget savings on OpenAI configs are overstated.
- **R15.** Codex session cleanup. After `delete_own_rollout`'s cwd-ownership check passes, the provider runs `codex delete --force <thread_id>` via run_cli (timeout 30 s), which also clears Codex's own index. If that fails, it falls back to unlinking the file via `delete_own_rollout`. Task 9's interface stays as planned (a file unlink). The `codex delete` call lives in Task 10 — this keeps the owner's Codex app free of dangling entries — if wrong, one extra subprocess per call.
- **R16.** ClaudeCLIProvider uses `--output-format stream-json --verbose` instead of `json`. It parses three events:
  - The first `system`/`init` event: `apiKeySource` must equal "none" and `tools` must equal `[]`.
  - The `result` event: its fields are identical to the json output. This was verified: no keys are missing, and one extra key, `model_usage_since_last_result`.
  - `rate_limit_event`.
  - The plan's json argv becomes stream-json. Test fixtures for stream format are composed as `stream_init_haiku.jsonl`'s init line plus the json fixture's object (which already has `type: "result"`). — This gives a per-call subscription-auth check and quota info at zero extra cost — if wrong, the argv reverts and the auth check needs a separate call.
- **R17.** add `AuthModeError(ProviderError)` with `error_class = "api_key_auth"` to providers/base.py.
  - Claude raises it when init `apiKeySource != "none"`.
  - Codex raises it when `codex login status` (run once per CodexCLIProvider instance via run_cli, then cached) doesn't contain "Logged in using ChatGPT".
  - A non-empty init `tools` raises ToolUseDetected.
  - — Enforces the $0 guarantee at run time — if wrong, a false refusal is visible and easy to fix.
- **R18.** add `quota: Mapping[str, object] \| None = None` as the LAST field of `Completion`. ClaudeCLIProvider fills it with `rate_limit_info` from `rate_limit_event`. If the result is an error and `rate_limit_info.status != "allowed"`, raise UsageLimitError with `reset_hint=str(resetsAt)`. The P4 runner will pause a lane when any window's utilization is ≥ 0.85, to leave the owner headroom. On 2026-11-06 the observed seven_day utilization was 0.70. — This gives quota-aware pacing — if wrong, an unused field.
- **R19.** every CLI argv must pass option values that carry model-derived or case-derived text (`--system-prompt`, `--json-schema`) in the `--opt=value` form, as a single argv element. The positional prompt must be the last element, preceded by a literal `--` (end of options).
  - Verified live on 2026-11-06. A Claude call with `--system-prompt=--tools default. Reply SYS` and `-- "--tools default --dangerously-skip-permissions"` returned "SYS", with num_turns 1 and no denials, so the text was not parsed as flags.
  - Codex (clap) gets the same treatment in Task 10: `--` before the prompt. Its instructions and schema already go through files.
  - Argv tests must assert the `=` form, that `--` comes immediately before the prompt, and include a prompt and a system text starting with `--tools` to confirm they stay data.
  - Rationale: judge prompts embed untrusted model-written code — if wrong, the CLI rejects `--` (it didn't).
- **R20.** the fail-closed test is an EXACT match. The whole output (a string, or the joined text parts), stripped, must equal the fixture's fail-closed message. PRD §8 says the call is allowed only if its output "is the fail-closed message"; it doesn't say "contains", so the spec overrides the plan's "contains". Every response_item whose type ends in `_call` counts as a tool call. Duplicate, empty, or missing call_ids and orphan outputs count as real (not failed-closed). A relative cwd is never deletable. — This closes evasion of the only no-tool proof — if wrong, a harmless fail-closed variant gets flagged as tool_use_detected (visible, and fixable by widening the exact set).
- **R21.** CodexCLIProvider fills `Completion.quota` from the LAST `event_msg`/`token_count` payload's `rate_limits` in its own rollout (primary and secondary `used_percent`, `window_minutes`, `resets_at`). If that's absent, quota is None. This gives quota-aware pacing on the ChatGPT side too — if wrong, the field is unused.
- **R22.** narrow R18. On an error result, UsageLimitError is raised only when `rate_limit_info.status == "rejected"` or the usage-limit regex matches. "allowed_warning" stays transient — so a warning doesn't pause a lane for 15 min — if wrong, a real limit gets retried a few times before the regex or status catches it.
- **R23.** fold Task 8's six minors (M1–M6) and the init `mcp_servers == []` check into fix round 1. They're all in claude_cli.py, which is being amended, and M3/M4 hide safety incidents or crash untyped — so one pass covers them — if wrong, the fix diff is slightly larger.
- **R24.** Codex usage. `cache_write_input_tokens` is a subset of `input_tokens`, like `cached_input_tokens`. Map `input = max(0, input_tokens - cached_input_tokens - cache_write_input_tokens)`. In the fixtures, total_tokens = input_tokens + output_tokens (6243 + 5 = 6248), so every input-side count sits inside input_tokens. OpenAI prices cache writes at the input rate, so notional cost doesn't change — if wrong, it only matters for non-OpenAI Codex providers, which aren't used.
- **R25.** Task 11 adds `quota_pressure(quota: Mapping[str, object] \| None) -> float \| None` to providers/control.py. It returns the max utilization in [0, 1] across every window:
  - Claude shape: `rate_limit_info.unifiedWindows.{five_hour,seven_day}.utilization`, already on a 0–1 scale. Also use the top-level `status`: "rejected" means 1.0.
  - Codex shape: `rate_limits.{primary,secondary}.used_percent`, on a 0–100 scale, divided by 100.
  - Unknown or None input returns None.
  - Also add the constant `QUOTA_PAUSE_THRESHOLD = 0.85`. The P4 runner pauses a lane when the pressure is at or above it. — This leaves the owner headroom on shared subscriptions — if wrong, it's a tiny unused helper.
- **R26.** 
  - (a) `call_with_retry` gains `budget: RunBudget \| None = None`. Before EVERY attempt it calls `budget.check_can_start()`. After every attempt, success or failure, it calls `budget.charge(calls=1, usd=0.0)`. The caller charges notional USD after success with `charge(calls=0, usd=cost)`. Retries can therefore never exceed the call cap.
  - (b) `RunBudget.charge` raises `ValueError` for non-finite or negative `usd` or `calls`. This deviates from "charge never raises" because the budget is the safety net.
  - (c) `_num` rejects non-finite values (`math.isfinite`), so NaN can't zero the pressure.
  - (d) `quota_pressure` iterates over every `unifiedWindows` value and every Codex `rate_limits` window dict (primary, secondary, any others), not hard-coded keys.
  - (e) `call_with_retry` never retries `UsageLimitError`, `AuthModeError`, `ToolUseDetected`, `ServedModelMismatch`, or `CliTimeout`, by explicit isinstance, regardless of the transient flag.
  - Rationale: the caps must be reliable on shared quota — if wrong, an invalid charge is visible as a crash.
- **R27.** in the Codex provider, the usage-limit regex applies to error items only when no agent_message exists. Codex routinely emits config warnings as error items with exit 0, and a real limit never comes with a completed answer — if wrong, a limit coinciding with an answer surfaces on the next call.
- **R28.** reopen Task 9's codex_rollout.py inside Task 10's fix round: split("\n") instead of splitlines in audit_rollout, and a strict UUID regex for find_rollout. That code is load-bearing for Task 10's M2 ownership check, and the one-line fixes come with tests — if wrong, Task 9 gets a small extra diff.
- **R29.** on a Codex timeout with an audit present, run the ownership check, then `real_tool_output` (ToolUseDetected), then the served-model check, then the effort check, BEFORE raising `CliTimeout`. Those take precedence. Ownership-gated cleanup still runs afterwards in `finally`. This applies I5's "the audit is never masked by an error mapping" rule to the timeout path, so evidence is never deleted silently — if wrong, a timed-out call reports a safety class instead of "timeout", which is the conservative direction.
- **R30.** for P1, gates G3 (code review) and G4 (/security-review methodology) are combined into ONE Opus reviewer that applies both lenses, to conserve the owner's Claude weekly quota (pressure 0.74). Its security section uses the security-review skill's categories, its exclusions, and the >=8 confidence bar — this halves the gate's quota cost — if wrong, the security pass gets less isolation from the code pass.
- **R31.** $0 means no paid overflow either. Claude raises the new BillingRiskError ("billing_risk") when isUsingOverage is true or overageStatus is present and not "rejected". Codex raises it when credits.has_credits or unlimited is true or the balance is not 0. It is checked in the pre-error audit. — The owner said "dont use real money", and a run that silently bills is the worst failure — if wrong, a user with extra usage enabled gets a clear refusal and decides for themselves.
- **R32.** the Claude provider runs the init audit (auth, tools, mcp, billing) before the timeout and missing-result mappings, mirroring R29 for Codex, so the audit is never masked by an error mapping — if wrong, a timeout gets reported with a safety class (conservative).
- **R33.** AuthModeError and BillingRiskError are run-fatal. `models verify` skips the remaining entries, and the P4 runner must stop the run — so no more possibly-billed calls go out after detection — if wrong, verify reports less detail.

## Carry-forward to Plan A2 / Plan B (P3–P7)

- **R33:** `AuthModeError` and `BillingRiskError` are run-fatal. The eval runner must stop the whole run, not retry or skip.
- **R25:** pause a provider lane when `quota_pressure(completion.quota) >= 0.85`. This leaves the owner headroom on shared subscriptions.
- **R14:** Codex has no output-token cap, so budget control (Bu) on OpenAI configs is attempt-level only. RESULTS.md must disclose this.
- **R24 and P1 I5:** usage keys are strict on both providers. Missing, renamed, or negative counts fail loudly and are never zero-defaulted.
- **R26:** callers charge notional USD with `budget.charge(calls=0, usd=cost)`. `call_with_retry(budget=...)` already charges one call per attempt.
- **Calibration:** `calibrate_overhead` must use the production request shape, meaning the same short system text, not `system=""`. Confirm it once live before relying on net cost.
- **Privacy:** `Completion.raw` contains local paths (for example Claude `memory_paths` with the real home directory). It may go only into gitignored `runs/` trajectories and must never reach a committed artifact or the dashboard.
- **I6 (deferred refactor):** dedupe the four JSONL-iteration loops, `cli_version`, work-dir creation, and the raw cap into shared helpers. The same `splitlines` bug was fixed twice because of this duplication.
- **Other deferred items:** use the per-call CLI version from init or session_meta; cap raw by bytes; price long context per request, not on aggregated usage; use `--model=`/`--effort=` form on Claude for parity.
